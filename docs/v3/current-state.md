## Architecture (approved target, not a claim of live cutover)

- **GitHub** is the single development origin (`dev` integration; `main` protected release). Project [#7](https://github.com/orgs/Skyline-Gazer/projects/7) and parent issue [#67](https://github.com/Skyline-Gazer/AiringCal/issues/67) track delivery. No CNB/QingLong/Docker deployment or Writer scheduler.
- **GitHub Actions** runs the sole one-shot Portable Writer. Release pointer, versioned manifest, immutable snapshot and original/WebP images live in **Cloudflare R2**. Every environment targets **one Bucket** (`airingcal-development`, later `airingcal-production`); object key prefixes `checkpoints/`, `public/`, `snapshots/`, `images/`.
- **Default public surface is the Reader Worker itself (`worker` origin mode).** R2 stays **private**: no anonymous custom domain, no `r2.dev`, no WAF/redirect exposure of bucket URLs. The single Worker per environment serves, next to the Viewer routes and read APIs, an allowlisted **public object interface** straight off the private R2 binding: `/public/current-release.json`, legacy `/public/manifest.json`, `/snapshots/v1/{generation}-{hash}.json`, `/public/manifests/{generation}-{hash}.json`, and `/images/{hash}/original|thumb.v1.webp|thumb.v2.webp`. Keys are rebuilt from regex-captured lowercase hex only, everything else (including `checkpoints/**` and any traversal or percent-encoded variant) is 404 before any object read; images are streamed with sniffed `Content-Type` and immutable cache. Cross-origin embeds are governed by the Worker via exact-origin `AIRINGCAL_CORS_ORIGINS` (no wildcards; OPTIONS preflight only when allowlisted, else 405). EdgeOne Reader and future Netlify/Vercel consumers use this same controlled interface — they never fetch raw bucket keys. `scripts/deploy-env.mjs` derives the mode from `AIRINGCAL_PUBLIC_BASE_URL`: unset (or a `*.workers.dev` Worker URL) = `worker` mode (no custom-domain/cache/CORS/WAF edge steps; the isolation probe runs **after** deploys against every deployed reader origin across plain, `%63`-encoded and `..%2f..%2f` variants, and the probe object is always deleted afterwards, with a positive S3 `HEAD` proof at write and probe-residue recovery that never weakens the production empty-bucket guard). A non-Worker `https://` base selects the **legacy `bucket-domain` mode** (custom domain + host-scoped WAF/cache/CORS, probe before copy) kept only for the already-live `airingcal.223.im` topology and as documented rollback. `checkpoints/` remains internal in both modes. **CORS is not authentication or anti-hotlink access control.** No image gateway Worker and no on-request image compression.
- **Workers Static Assets (`[assets]`) was evaluated and rejected** for this plane: the generated Reader/Widget assets are served today by the same inline handler in every runtime (Cloudflare Worker, Node `serve-node`, miniflare, bun), and binding `[assets]` would fork delivery semantics (cache classes, ETag/304, 405/410 contract) between CF and non-CF runtimes while adding a second publish step to the release pipeline. The single-Worker requirement is satisfied without it; revisit only if asset volume makes inline shipping a cold-start cost.
- **Cloudflare and EdgeOne** are stateless Reader targets consuming one verified Release. EdgeOne Reader Makers project is `overseas` (unfiled domain); optional EdgeOne **image CDN** may use a separately filed domain and HTTPS R2 origin with correct Host/SNI; `AIRINGCAL_IMAGE_BASE_URL` defaults unset.
- Writer/Release CAS, fencing, single-authority rule, rollback contracts are unchanged. Snapshot cached per isolate (60-second soft pointer recheck); image route avoids full snapshot load; widget UX improvements are merged, **not** yet validated under new Development live deployment.
- **Read gateway contract (enforced in `packages/v3-read`, all runtimes):** GET/HEAD only (405 + `Allow`, deprecated sync routes keep 410); allowlisted routes only — including the public object interface above, whose keys never pass a caller string to the store; snapshot routes serve release-identity `ETag` with `If-None-Match`→304; pointer-supplied `artifact_ref`/`manifest_ref` must be the exact content-addressed keys before any object read. Anonymous checkpoint isolation on public entrypoints is unchanged and still proven by the deploy isolation probe (bucket domain in legacy mode, deployed reader origins in worker mode).

## Config and deployment gates

1. Do **GitHub Issue / PR / Project #7 reconciliation and documentation cleanup first**; check the state of [#67](https://github.com/Skyline-Gazer/AiringCal/issues/67), [#72](https://github.com/Skyline-Gazer/AiringCal/issues/72), [#73](https://github.com/Skyline-Gazer/AiringCal/issues/73), and [#147](https://github.com/Skyline-Gazer/AiringCal/issues/147). P2 engineering [#71](https://github.com/Skyline-Gazer/AiringCal/issues/71) is completed/closed. Avoid unnecessary new Issue/PR proliferation or Project Status columns.
2. Worker mode (the default) needs **no public bucket URL**: leave `AIRINGCAL_PUBLIC_BASE_URL` unset (or point it at the Worker's own `*.workers.dev` URL). Only the legacy `bucket-domain` mode requires a **real R2 custom-domain URL in the same Cloudflare account's Zone** as the target Bucket — never blank-but-nonempty placeholders or the `r2.dev` URL there. Derive or verify `AIRINGCAL_ZONE_ID` from zone ownership, never guess a Zone ID. Confirm EdgeOne Token/CLI authentication and legacy key mapping before modifying resources.
3. Use locally ignored `.env` based on [`.env.example`](../../.env.example): `AIRINGCAL_ENV=development`, `AIRINGCAL_DEPLOY_TARGET=both`, Cloudflare API Token, account ID (if needed), Zone ID, R2 public base, Bangumi identity, EdgeOne API Token. Cloudflare token can derive R2 S3 credentials **only after real S3 permissions verification**; no extra R2 keys on the normal happy path.
4. **Read-only preflight must pass before any Writer freeze:** domain availability/ownership, zone and token scopes, existing staging writer/workflows, R2 and EO CLI commands, target config, absence of conflicting public access.
5. After explicit Owner authorization, follow [reader-delivery-cutover.md](reader-delivery-cutover.md): freeze old staging writer, prepare `airingcal-development`, disable its `r2.dev`, apply host-scoped WAF/CORS/cache, verify a non-sensitive checkpoint probe is anonymous-denied, **then** copy real checkpoint/public data, sync GH Environment, deploy Reader, verify 302/parity, single Development Writer test with flag safely restored, apply MIME metadata repair and collect post-bench/CWV receipts. **Do not disable legacy staging rollback endpoints.**
6. Staging Accepted requires actual evidence: HEAD `image/*` for original/thumbnail; CF+EO generation/hash parity; meaningful cache/rollback metrics; LCP/CLS/INP measured when browser available; no fictitious CDN HIT or mainland results. Keep Production off.
